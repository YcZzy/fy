## 云端协议与部署依赖

本轮升级为协议 2。同步写入统一经过 `cloudfunctions/dataManager/index.js`，按调用者身份处理；每个用户有独立重置版本。服务器以小批事务删除记录，防止在途同步、重复删除与下一轮新数据互相干扰。照片仍在调用者权限下删除，不使用服务端管理员权限删除客户端给出的文件 ID。

需要配套部署云函数、创建 `sync_control` 并应用权限文件。**这些文件已修改，但本轮没有部署真实云端，也没有上传或发布小程序。** 精确集合、规则文件与升级步骤见根目录 `README.md`。业务集合禁止客户端直接写入，`sync_control` 禁止客户端读写；旧客户端与新规则不能作为同一版本发布。

新客户端遇到旧后台协议会保留本机数据并提示未完成同步。已经启动但失败的全部删除会暂停同步，保留重试进度。云端只保留防止旧设备恢复数据所需的重置标记。

## 验证结果与边界

- `npm run check`：页面完整性、JSON、JavaScript 语法、事件绑定检查；仓储、推荐、同步、照片删除、云端协议测试；29 个页面与完整流程场景。
- `npm run check:native`：使用本机微信原生编译器检查 11 个 WXML 与 12 个 WXSS，覆盖 10 个页面、自定义底部栏和全局样式。
- `git diff --check`：检查修改中的空白格式问题。
- 云接口使用隔离模拟，未访问实际 CloudBase 或实际用户数据。事务模拟验证业务顺序，不代表已经验证云端限额、真实事务冲突重试、网络延迟或权限部署。
- 未完成模拟器截图、真机小屏/大字体/软键盘视觉验收，不能把原生编译通过等同于所有设备布局正确。

基线取证文件 `reproduction-results.json` 保持不变。`reproduce.cjs` 是验证修改前缺陷存在的历史脚本，修复后预期不能继续通过，不属于当前验收命令。
